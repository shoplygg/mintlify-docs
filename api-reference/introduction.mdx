The Shoply API is everything the dashboard does, for a program instead of a person. With a secret API key your own server can manage a store's catalogue and stock, read and complete orders, refund them, look after customers and affiliates, run coupons and sales, keep the books, and be told the moment something happens.

```
https://api.shoply.gg/v1
```

## How it is shaped

Every route but one is under `/stores/{storeId}`. Nothing here is an account's: a product, an order, a customer is one store's. A key is one store's too, and reaches no other.

An answer has one shape, a success and a refusal alike. A key carries permissions, and each route's page says which one it needs. Requests are counted for each key, and every answer says how much of its budget is left.

## What it is not for

A browser. A secret key in a page is readable by every visitor of that page, so the API sends no CORS headers and a browser refuses to read its answers. For a storefront of your own, use the [Storefront SDK](/sdk/introduction), the [embed](/guides/embeds) or the [Checkout Kit](/guides/checkout-kit): they need a store ID and no key.

A few things are also left to a person in the dashboard, where it asks them to confirm it is them: a payment method's credentials, the dynamic delivery signing secret, where the store's alerts are sent, and API keys themselves. A key that tries one is refused with `dashboard_only`.

## Being told, instead of asking

If you are asking the API over and over whether an order has been paid, use [webhooks](/api-reference/webhooks). They arrive in the second the thing happens, signed, and are tried again for a day if your server is down.
